从「有氛围」到「有精度」

当前皮肤的氛围层（角色、废墟、开屏、粒子）已经完整，但界面层缺少一套可复用的尺度系统：字号、字距、间距、圆角、描边、阴影、动效时长都是逐个组件手调的零散数值，深浅色又各自硬编码。这正是「粗糙」的来源——不是素材不好，而是没有栅格与层级规则把它约束住。本页盘点现有设计资产，逐条定位问题，并给出可分级落地的精细化方案。

01

设计资产盘点

现状有什么 / 精细度如何

皮肤共 8 个视觉模块。评级指「是否已有统一尺度约束」，不是指工作量或观感好坏。

M-01

令牌层 · 89 keys

全量覆盖平台 alias/specific 令牌，浅深双值成对，门禁 89/89。是全局配色的唯一权威来源。

M-02

场景层 · 废墟/雪原

纯 CSS 天空、雾带、地面、环形准星、机械眼；另有 Canvas2D 粒子四档。色源散在 3 处。

M-03

右下 2B 角色

相交 mask 避让文字、双关节 24s/5.6s 异步摆动、接触阴影、掠光。工程完成度最高。

M-04

左下 A2 档案卡

浅色装裱为骨白档案卡，深色为满浓度壁纸。浅色卡的边框/阴影/说明文字尚未对齐栅格。

M-05

HUD 角标与读数

四角括号 + 左下等宽状态行。尺寸 22px、边距 14/18/16px 均为自由值，视觉偏重。

M-06

YoRHa 控制条

可拖动、四键、位置记忆。gap 1px / padding 4px / 按钮 6×9px 全是非栅格值，无拖拽把手。

M-07

六幕开屏动画

自检幕 → 准星 → 打字机 → 进度条 → 诊断框 → 揭幕。内容完成，但排版密度与进度条发光偏「粗」。

M-08

字体与全局规则

Segoe / Bahnschrift / Cascadia Mono 三套，方角化与全大写用 !important 全局施加，中文被误伤。

关于外部那份「语义色」建议：它提出用「电蓝 / 亮绿 / 黄色琥珀 / 亮红」，但本皮肤明令禁止青蓝、橙、暖金（HANDOFF §4-3，且「青蓝违规」曾是「不够尼尔」的根因）。所以不能照抄配色表。可行解是：保留尼尔色相，只拉开明度，并用形状/图案冗余区分状态（实心点 / 空心点 / 斜纹 / 无线条）——既守住配色，又比单靠颜色更可辨、对色弱更友好。见 04 节对照 B。
03

精细化设计系统（提案）

七组私有变量 · 不占平台令牌名额

新增变量统一用前缀 --nier-，写在自注入 <style> 的 :root 里。令牌门禁只校验 TOKENS 对象里的 --dsw-* 键，因此新增私有变量不会破坏 89/89——这是整套方案能零风险落地的关键。

RULE-01

CJK 单独一档

:lang(zh) 与 [lang|="zh"] 下把 letter-spacing 归零或减半、关闭 uppercase；拉丁标签继续用 .12em。这是中文界面「精不精细」最立竿见影的一处。

RULE-02

规则限域，不用全局 !important

方角化/大写字距从 body button 收窄到皮肤自己的 #dsh-skin-nier-* 组件与短标签，宿主控件交还给平台样式，避免误伤与升级脆弱性。

RULE-03

色源收敛到一处

场景层的 --nier-sky / --nier-city / --nier-fog 及浅深两份覆盖，统一从 TOKENS 派生；浅色规则尽量写成变量差值，而不是第三套硬编码。

05

实施分级与顺序

先零风险，后低风险，组件层不做
T0零风险只改数值

令牌数值微调 · 不动任何结构

  • 拉开 11 个 state-* 令牌的明度/对比度，尤其让 error 与 warn、success 与 secondary 分开。
  • 统一三个既有 --ds-transition-duration* 到 80/140/240ms。
  • focus outline 的 offset 与 border 透明度微调。
  • 验证：verify-tokens.mjs 仍须 89/89 / 0 / 0；status.mjs 18 项全 OK。
T1-a低风险新增私有变量

建立尺度系统 · 本页第 03 节

  • 在自注入 <style> 的 :root 新增 --nier-space-* / --nier-type-* / --nier-track-* / --nier-radius / --nier-elev-* / --nier-motion-*。
  • 加 :lang(zh) 归零规则；把全局方角化/大写规则收窄到皮肤自有组件。
  • 不进 TOKENS 对象 → 门禁不变；不新增 DOM 层 → 稳定性契约不变。
T1-b低风险逐个组件

组件对齐尺度 · 本页第 04 节 A–G

  • 建议顺序：档案卡 C → 控制条 D → HUD E → 开屏 G → 扫描线 F → 按钮 A。
  • 每改一个出一次预览截图确认，再改下一个（沿用既有「预览先行」流程）。
  • 禁止使用全局 transform、禁止新增全屏定位层、禁止改动 z-index 与可读性 mask。
T1-c低风险形状冗余

状态标签 B · 回应外部文档「步骤 2」

  • 用点形状/斜纹/描边承载语义，而不是引入琥珀与电蓝。
  • 需要找到稳定的 [data-state] / [data-running] / [data-variant] 钩子；若平台组件未提供稳定钩子，这一项可以整体放弃，收益不值得冒险。
T2不做越界

明确排除

  • 骨架屏 / Toast / 空状态文案：属于 React 组件逻辑，皮肤是纯客户端注入，做不到（除非改宿主前端包）。
  • 整体移除全局方角化：会显著改变宿主观感，属于「重做设计」而非「精细化」。
  • 重选风格方向、引入霓虹紫/暖金/青蓝：违反 HANDOFF §4-3 配色红线，并推翻已确认的深色 A / 浅色档案卡方案。

06

不可越过的红线

来自上一轮的稳定性契约
01

只改唯一编辑源

src/client.template.js。lib/client.js 是构建产物，会被覆盖；profiles\web 那份 v1.0.0 是未注册的孤立副本，改了没有效果。

02

令牌门禁 89/89

只能覆盖已有 --dsw-* 键，不能新增。新增 UI 一律走自注入 <style>、自定义事件、body class 或 --nier-* 私有变量。

03

可读性不变量

角色层天然在正文之上。不得新增覆盖全屏的不透明定位层，不得用 z-index:-1，边缘渐隐 mask 与物理避让是唯一安全解。

04

宿主零影响

每个挂载仍须过 guard()/keep()，disposer 逐个 try/catch，开屏看门狗 20s 保留；异常绝不逃逸到 Cordis。改完必跑 tools/stability-test.html 的 20 条断言。

05

严格尼尔配色

黑 / 白 / 红 #a3262e · #d2454e / 冷枪灰；禁青蓝、橙、暖金（A2 壁纸原色除外）。哑光、无发光、无液态玻璃。

06

性能护栏

DPR≤1.5、隐藏停绘、prefers-reduced-motion 静止、窄屏停绘、滚出视口停绘。新增动画必须沿用；本提案只减不加动画。
